Adds `php`/`composer`, `pwsh` with PSScriptAnalyzer, `cmake`/`ninja`/`pkg-config` and opt-in `ccache`, `go` with `golangci-lint`, `dotnet` (SDK 10.0), `opa`, `gitleaks`, `psql` with a PostgreSQL 16 server (`pg-dev-up`), `sqlcmd`/`bcp`, `marp`, `mmdc`, `chromium`, the `playwright` CLI, and rootless `podman` with a `docker` shim. Before first using one of them in a session, read its row in `/usr/local/share/agent-reference/tooling.md`, under "Contributed by the `full` layer set": pinned versions, caches, and what each needs before it works.

- **Go tests and memory.** Several worktrees each running a Go test suite at full parallelism exhaust the container's memory. The sign is a killed process or an unrelated timeout, never an error that names memory. When suites run in more than one worktree at once, cap each one (`go test -p <n>`, `GOMAXPROCS=<n>`) or run them in turn.
- **PowerShell lint.** `Invoke-ScriptAnalyzer` is a `pwsh` cmdlet, not a shell command, and without `-Recurse` it checks only the scripts directly in the given directory, which reads as a clean pass: `pwsh -Command "Invoke-ScriptAnalyzer -Path . -Recurse"`.
- **PostgreSQL.** No database daemon runs by default. `pg-dev-up` starts a throwaway local cluster and prints its `DATABASE_URL`. Parallel worktrees that run database tests each need their own cluster (`pg-dev-up --worktree up`), or they share one data directory and port. Read `local-postgresql.md` in the reference directory when a suite needs a live database.
- **Containers.** `docker` is a shim for rootless `podman`; there is no Docker daemon. Reach a nested service through its published port on `localhost`, not its in-container IP. Judge a nested container's memory trouble by its exit code and logs: `podman inspect` can report `OOMKilled: true` for one that never ran short. The Containers row has the rest.
- Playwright's browsers are not baked, and the system `chromium` does not stand in for them. The Playwright row has the one-time install and what a programmatic script needs.
