# Smoke test stage inventory

Agent-facing reference for what `commands/smoke-test.sh` actually covers, stage by stage: what each stage asserts, where it runs, and when it self-skips.
Routed from [AGENTS.md](../AGENTS.md) and from the README's [Host Validation](../README.md#host-validation) section, which keeps only the invocation and points here for the detail.
The smoke tier needs a real built image and, in places, a relaunchable container, so it runs on the host or in CI — never from inside an agent container (see [AGENTS.md](../AGENTS.md) → "Validating Changes").

```bash
./commands/smoke-test.sh [image]        # defaults to powbox-agent:latest
```

The run is layered: a **Stage 0 tier** of nine hermetic unit-suite entries (Stages 0 and 0a–0h, over seven distinct `scripts/test-*.sh` files), followed by **six image/host stages** that exercise the built image and the host.
`POWBOX_SMOKE_REQUIRE_IMAGE=1` (used by CI, and exported to every sub-script) turns an absent image into a hard error before any stage runs, instead of letting the image-gated checks self-skip into a false "all green".

## Stage 0 tier — hermetic unit suites

Every entry here is a pure-shell suite, and "hermetic" means it needs no root, no host database, no nested container engine, no relaunch cycle, and no network.
It does **not** mean container-free: only **Stage 0** and **Stage 0c** run purely on the host, while the other seven entries (0a, 0b, 0d, 0e, 0f, 0g, 0h) issue a `docker run --rm … "$IMAGE"` so the suite executes inside the image.
Six of those seven (0a, 0b, 0d, 0f, 0g, 0h) point the suite at the **baked** artifact under `/usr/local/bin/` rather than the `/repo` source, so a stale or behaviorally broken baked copy is caught by a real suite instead of being waved through by Stage 1's `command -v` presence probe; Stage 0e runs in-image only for the toolchain, since what it validates is a `/repo` script with no baked counterpart.
How each entry pairs host and image differs, and the distinction matters when the image is absent: Stages 0a and 0d are the baked halves of the host runs at Stages 0 and 0c, and simply record a skip when there is no image (the host half already covered the source); Stages 0b, 0e, 0g and 0h run in-image *instead of* on the host, falling back to a host source run only when the image is missing **and** the host toolchain qualifies; Stage 0f is the only entry that runs twice when it can — the host `/repo` source and the baked helper.
Seven distinct suites back the nine entries, because `test-sensitive-host-path.sh` (Stages 0/0a) and `test-wt-orphan-safety.sh` (Stages 0c/0d) each appear twice.

- **Stage 0 — `sensitive-host-path` predicate + `/proc/self/mountinfo` parser** (`scripts/test-sensitive-host-path.sh`, host `/repo` source). Guards the classifier that stops the workspace-perms heal from recursively chowning a mount whose host source is a system or home directory (the VPS-lockout incident: an accidental `cc`/`cx` from `~` re-owning the home tree and breaking sshd `StrictModes` on `~/.ssh`). Needs no image, root, or native-Linux host, so it always runs; the live end-to-end guard is Stage 5.
- **Stage 0a — the same test against the BAKED library** (in-image, `SENSITIVE_HOST_PATH_LIB=/usr/local/bin/sensitive-host-path.sh`). Exercises the copy that `entrypoint-core.sh`, `fix-workspace-perms.sh`, and `heal-workspace-perms.sh` actually source at runtime. Records a skip when the image is absent — Stage 0 already covered the source, so there is no second host run.
- **Stage 0b — `gh-review-threads` helper** (`scripts/test-gh-review-threads.sh`). Stubs `gh` with a PATH shim serving canned fixtures, so no live GitHub is needed. Guards manual pagination (never `gh api graphql --paginate`, which under concurrent runs has returned another PR's threads) and the boundary-safe, repo-qualified PR-scope assertion that fails closed with exit 3 on a contaminated response. Prefers the in-image run against the baked helper; the host fallback needs both the staged `.agent-skills-src` clone (the helper is vendored in `Roubtec/agent-skills`, not in-tree) and host `jq`, else the stage records a skip.
- **Stage 0c — worktree orphan safety** (`scripts/test-wt-orphan-safety.sh`, host source, a throwaway git repo in a tmpdir). Guards the durable-worktree-metadata safety contract (task 017): a directory that is no longer a live worktree is reaped only when EMPTY and otherwise PRESERVED under `.worktrees/.orphaned/`, so `wt-bootstrap`/`wt-enter`/`wt-remove` never delete the sole surviving copy of dirty work when metadata disappears.
- **Stage 0d — the same suite against the BAKED `wt-*` helpers** (in-image, `POWBOX_WT_COMMON`/`POWBOX_WT_ENTER`/`POWBOX_WT_REMOVE` → `/usr/local/bin`), including their exec bits. Records a skip when the image is absent rather than re-running on the host.
- **Stage 0e — Podman Compose exec-form health-check probe invariants** (`scripts/test-podman-compose-healthcheck.sh`, task 025). Parses the fixture embedded in `scripts/smoke-test-podman.sh` with `yq` and asserts that Stage 3's health check stays an exec-form `CMD` array (not `CMD-SHELL`), that the probe inspects and classifies the wired translation so a `CMD`→`CMD-SHELL` rewrite surfaces as a detected KNOWN-XFAIL rather than a silent pass, that it drives the check and requires `healthy` while a never-succeeding negative control is driven to the terminal `unhealthy` state (not merely "not healthy"), that cleanup tears down the project and only the temp dir, and that the Bash and PowerShell probes stay in parity. It validates the `/repo` source (`smoke-test-podman.sh` is a repo script, not a baked artifact), so a host run suffices — but it needs the jq-backed `yq -r <filter>` interface, so the in-image run is preferred and the host fallback is gated on the test's own `--check-yq` capability probe rather than a bare `command -v yq`.
- **Stage 0f — `peer-review-run`** (`scripts/test-peer-review-run.sh`). Fake `claude`/`codex` binaries on a per-case PATH, so no real providers, image, or network. Guards the versioned result schema, both provider directions, the read-only permission flags, literal stdin-fed prompts, Codex progress forwarding, the six normalized outcomes, timeout with process-tree reaping, and retry-once. The host run is gated on a Linux host with `jq` (the helper and test lean on `/proc/<pid>/stat`, `pgrep -P`, GNU `realpath -m`, `date +%N`); the in-image run additionally exercises the baked `/usr/local/bin/peer-review-run` and passes `--init` so descendants killed by the reap assertions are collected instead of lingering as zombies, matching the reaping PID 1 the powbox runtime always provides.
- **Stage 0g — `detect-shadows` suite** (`scripts/test-detect-shadows.sh`, task 053). The only regression net for `docker/shared/detect-shadows.sh`'s load-bearing security properties: the under-workspace-root validation, the symlink skip, the Git-tracked-content veto and its fail-closed paths, the newline rejection, and the workspace-glob containment. In-image it points at the baked `detect-shadows.sh` and `pnpm-shadow-doctor` (`POWBOX_DETECT_SHADOWS` / `POWBOX_PNPM_SHADOW_DOCTOR`); the host fallback needs both a Linux userland (the script under test calls GNU-only `realpath -m --` and drives its .NET artifact scan through `find -H … -printf '%h\0' | sort -zu`) and a pass from the suite's own `--check-deps` probe (git, jq, and the jq-backed python-yq — mikefarah's Go `yq` rejects the filters `detect-shadows.sh` issues). Tier 0 CI also runs the suite unset on every PR.
- **Stage 0h — `shadow-mounts` mountpoint ownership** (`scripts/test-shadow-mounts-chown.sh`, task 053). Copies `docker/shared/shadow-mounts.sh` with its `/workspace` literal relocated into a tmpdir and PATH-shims `id`/`stat`/`chown`/`mount`/`mountpoint`, so it asserts the chown/mount decision logic without root or a real mount: every created mountpoint component inherits the DEEPEST EXISTING ancestor's `uid:gid` **before** the mount goes on top, with exactly one warning per run when that fails. In-image it points at the baked `/usr/local/bin/shadow-mounts.sh` (`SHADOW_MOUNTS_SH`), the copy that actually runs under sudo in a live container; the host fallback is Linux-only because the code under test calls GNU-only `realpath -m --` / `realpath -e --` while the suite deliberately leaves `realpath` unshimmed. Its privileged end-to-end counterpart (real root, real bind mount, real ownership on disk) is Stage 6.

## Stages 1–6 — image and host stages

- **Stage 1 — tool presence and key image config** (`scripts/smoke-test-image.sh`). Every expected CLI resolves and runs, plus the image configuration that can regress silently: `pnpm config get package-import-method` is `auto` (not the old forced copy, so worktree installs hardlink from a co-located store); a stub in `$HOME/go/bin` is runnable by bare name, proving the baked `profile.d` snippet restores that PATH entry in a login shell; the `golangci-lint` cache-scoping wrapper (the PATH name resolves to the wrapper with the real binary off PATH in `/usr/local/libexec`, a fixture worktree scopes its cache under `.worktrees/.golangci-cache/<container>/<slug>`, the main checkout scopes to `.root` only in self-hosted mode, and a caller-set `GOLANGCI_LINT_CACHE` always wins); `GOMODCACHE`/`GOCACHE` honoring the plain env the launcher exports; a **functional** `ccache` check (two identical `ccache gcc` compiles into a fresh cache produce a direct or preprocessed hit, read from the machine-parsable `--print-stats` counters); an `opa test` round-trip over a generated Rego policy plus test, the exact contract a policy repo's CI runs; and the .NET SDK's two first-use sentinel files (present under `$HOME/.dotnet`, owned by the runtime user, and named for the same SDK version `dotnet --version` reports) plus its four documented env opt-outs. Each probe is handed to the driver as a **separate argument** and executed in its own `sh -ec`, so probe text is data rather than script, a failure is reported by index against a printed manifest, and no probe can affect the runner or a neighbour; `scripts/test-smoke-probe-wrapper.sh` unit-tests that runner, its injection-proofness, the per-probe isolation, and `.sh`/`.ps1` argv parity — but it is a hand-run suite, wired into neither this stage nor CI (see `tasks/059-wire-pure-shell-suites-into-ci.md`).
- **Stage 2 — `pg-dev-up` functional test.** Stands up a real throwaway PostgreSQL cluster and connects through the emitted `DATABASE_URL`, exercising role/db creation, URL percent-encoding (with deliberately nasty credentials), the `127.0.0.1` host binding, the `?sslmode=disable` DSN parameter (task 035 — Go `lib/pq` refuses to connect without it), and the `eval` export round-trip — none of which `pg-dev-up check` (binary presence only) can reach. It then checks worktree scoping: two **linked** worktrees of one repo each get an isolated cluster on a distinct allocated port, connect to their own database, and stop independently.
- **Stage 3 — rootless Podman engine** (`scripts/smoke-test-podman.sh`). Runs the image with the launch-time device and security wiring the launcher normally supplies via the compose overlays, so a base/Podman bump that regresses the engine is caught. It covers the static engine wiring (engine present, the baked `containers.conf` drop-in pinning `firewall_driver=iptables`, `podman info` reporting rootless/cgroupfs/netavark, and the `podman compose` subcommand) and the nested behavior (a nested container run, a bridge network with a published port, and a Compose exec-form health check driven through `docker compose` — the shim spelling agents use, which routes to `podman compose`). The health-check block has three services so it cannot pass vacuously: a positive `hc` service that must reach `healthy`, a `/bin/false` negative control that must be driven to terminal `unhealthy`, and a shell-less distroless service that actively reproduces the podman-compose `CMD`→`CMD-SHELL` rewrite as a reported KNOWN-XFAIL (self-skipped, and recorded in the banner, when that image cannot be pulled). See [rootless-podman.md](rootless-podman.md) → "Compose health-check behavior".
- **Stage 4 — self-hosted (`--isolated`) launch mode** (`scripts/smoke-test-selfhosted.sh`). Stage A validates the launcher's self-hosted identity contract through the `POWBOX_PRINT_IDENTITY` hook (which exits before any Docker call) and so needs no image, daemon, or network; Stage B validates the baked `seed-workspace.sh` clone/reuse/`--reclone`/failure behavior and the single-mount hardlink layout against the image, self-skipping when the image is absent. Stage B is the one stage that needs the **network**: it clones a small public repo (`POWBOX_SMOKE_PUBLIC_REPO`, default `octocat/Hello-World`), and two of its ref cases assert against contents specific to that default, so they self-skip against a custom fixture repo unless `POWBOX_SMOKE_REF_PATH`/`POWBOX_SMOKE_REF_BRANCH` are supplied. `POWBOX_SMOKE_SKIP_SELFHOSTED_CLONE=1` runs Stage A only, and that partial coverage is recorded in the banner.
- **Stage 5 — native-Linux dir-mount ownership** (`scripts/smoke-test-dirmount.sh`). A bind-mounted root-owned repo is `root:root` inside the container, which the `node` agent (uid 1000) cannot write; the entrypoint's write probe plus the sudo-allowlisted `fix-workspace-perms.sh` helper chown it so git and edits work. Six cases run. Two cover the heal itself: an all-root-owned mount (PR #55, task 005a) exercising the root-level write probe, and a mixed-ownership mount (task 007, task 007a) — a node-owned root hiding nested root-owned files from a host `sudo git pull` — exercising the nested-uid-0 detection scan the root-level probe misses, so reverting only that scan now fails the smoke. Both drive the genuine extracted decision unit `heal-workspace-perms.sh` (the byte-for-byte probe-and-call code `entrypoint-core.sh` runs), so the stage guards the decision path and not merely the helper, and both assert `node` can write and `git commit` afterwards. Four more guard the **sensitive-source refusal**, the live end-to-end counterpart of Stage 0's predicate unit test: `sensitive-skip` (a root-owned fixture launched with `POWBOX_WORKSPACE_HOST_PATH=/root`, so the heal must skip the chown and warn — the launcher-env fallback consulted when no marker is recorded), `fix-mountinfo-backstop` (a read-only bind of the host `/etc`, so `fix-workspace-perms.sh` — the privileged boundary, run under sudo with env stripped — must refuse via the `/proc/self/mountinfo` fallback source), `fix-true-source` (task 009 Gap A — a non-sensitive mountinfo source but a recorded marker true source of `/home/alice`, so `fix` must refuse via the marker, which survives sudo's `env_reset`, where the mountinfo-only backstop would have chowned), and `heal-true-source` (task 009 Gap B — a safe `/projects` marker true source alongside a deliberately sensitive env, so the heal must HEAL rather than skip, marker authoritative). No case boots the full entrypoint chain. It self-skips when the image is absent (honoring `POWBOX_SMOKE_REQUIRE_IMAGE`), when it cannot create a root-owned fixture (no root or passwordless sudo — the local-dev case), or when the host masks the native-Linux uid bug; CI runs it for real.
- **Stage 6 — durable worktree-metadata recreate lifecycle** (`scripts/smoke-test-worktree-metadata.sh`, task 017). The headline acceptance criterion: in dir-mounted mode a linked git worktree and its per-worktree admin metadata survive a container stop/recreate, because the metadata is bound from the persistent `.worktrees` volume over `.git/worktrees` rather than living in the tmpfs shadow that vanishes on recycle. It launches two throwaway containers on one named `agent-wt`-style volume — the first establishes the durable bind via the real `shadow-mounts.sh` and leaves a linked worktree DIRTY (a tracked modification plus an untracked file), the second recreates on the SAME volume. Four properties are then asserted: `git status` still works and HEAD is on the worktree branch; both dirty changes survived; the dir-mounted checkout's own `.git/worktrees` gained no container registrations; and — added by task 053 — every mountpoint directory `shadow-mounts.sh` had to CREATE inherited the `uid:gid` of its deepest pre-existing ancestor instead of being left root-owned. That fourth assertion runs on the **host** after Container A exits, so a plain `stat` sees the underlying directory rather than the mount stacked on it, and covers `proj/bin` (one created component, ordinary tmpfs path), `.claude/worktrees` (two created components), and `.git/worktrees` (one created component, but through the durable-bind branch); `.worktrees` is deliberately not asserted, since the container engine creates that mountpoint for the named volume and it is legitimately root-owned. Stage 6 needs the image and a runtime that can grant `CAP_SYS_ADMIN` for the `mount --bind`, self-skipping otherwise; CI runs it for real.

The fourth assertion compares each mountpoint with its ancestor rather than with `$(id -u)`, so a squashing filesystem (a Windows/FUSE bind mount) passes instead of failing spuriously — at the price of three conditions where a green proves nothing: a squashing filesystem, a rootless engine (the container's root maps to the invoker), and the smoke itself run as root on the host.
The latter two are detected and announced in the log; the first cannot be probed portably.
Real teeth come from an unprivileged host user on a rootful Linux engine — the native-Linux CI runner, and a stock Linux desktop install.

## Partial runs, host gates, and skipping

Several stages self-skip rather than fail when the host cannot provide what they need, and skips — whether requested or decided at runtime by a child script through the `POWBOX_SMOKE_SKIP_MARKER` mechanism (Stages 3, 5 and 6) — are collected and printed in an end-of-run banner, so a partial run is not reported as "all stages ran".
One runtime self-skip is not marker-wired: Stage 4's child skips its Stage B (clone behavior) when the image is absent and says so only in its own output. That is unreachable in a real run — a missing image fails Stage 1 and aborts before Stage 4 — so the banner is complete for any run that gets that far; the explicitly requested form (`POWBOX_SMOKE_SKIP_SELFHOSTED_CLONE`) *is* recorded.

- On a host that cannot expose `/dev/net/tun` (for example the Docker Desktop VM under the default `auto`), Stage 3 still validates the static engine wiring but skips only the nested-run and published-port checks; force the full check with `POWBOX_PODMAN=on`, or skip the whole stage with `POWBOX_PODMAN=off` (deprecated alias `POWBOX_FUSE=off`). A genuinely broken image — missing engine, dropped drop-in — fails the stage on any host.
- **Five** of the six image/host stages are gated by independent environment variables — Stages 2 through 6: `POWBOX_SMOKE_SKIP_DB` (Stage 2), `POWBOX_SMOKE_SKIP_PODMAN` (Stage 3), `POWBOX_SMOKE_SKIP_SELFHOSTED` (Stage 4), `POWBOX_SMOKE_SKIP_DIRMOUNT` (Stage 5), and `POWBOX_SMOKE_SKIP_WORKTREE_META` (Stage 6). Setting all five leaves the Stage 0 tier plus Stage 1 — no host database, no nested engine, no relaunch cycle — though the seven in-image Stage 0 entries and Stage 1 itself still start throwaway containers from the image.
- Stage 1 has no skip variable of its own — it is the residue that remains when all five are set. It is the presence sweep every later stage assumes, and a missing image makes it fail and abort the run before any later stage executes, so there is nothing to gain from skipping it.

## The PowerShell mirror

`commands/smoke-test.ps1` runs the same inventory wherever `pwsh` runs, including a native-Linux host, and takes `-SkipDb -SkipPodman -SkipSelfHosted -SkipDirMount -SkipWorktreeMeta` plus `-RequireImage` in place of the environment variables.

Two structural differences from the Bash umbrella — the first forced by Windows having no native bash, the second simply not built yet:

- It has seven Stage 0 entries (0, 0b, 0c, 0e, 0f, 0g, 0h) rather than nine. Every one of them runs **inside the image** — there is no host-source fallback at all, so the Bash tier's separate host-source-then-baked pairs (Stage 0/0a and Stage 0c/0d) collapse into one entry each, and every entry self-skips when the image is absent, where the Bash tier would still have covered the `/repo` source on the host. Six of the seven (0, 0b, 0c, 0f, 0g, 0h) point the suite at the baked artifact via the same env overrides the Bash tier uses; Stage 0e does not, because what it validates — the fixture embedded in `scripts/smoke-test-podman.sh` — is a repo script with no baked counterpart, so it runs in-image purely for the `yq`/`jq` toolchain.
- Stage 6 does not yet mirror the mountpoint-ownership assertions, so a full smoke driven through the PowerShell umbrella does not exercise that check. The divergence is recorded in `scripts/smoke-test-worktree-metadata.ps1`'s header and tracked as `tasks/053a-mirror-mountpoint-ownership-smoke-in-powershell-driver.md`; until it lands, run `commands/smoke-test.sh` on Linux for the ownership coverage.
